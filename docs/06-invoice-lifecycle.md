# 账单配置与账单生命周期

## 1. 账单配置

账单配置决定：

- 合并出账的合同计费项。
- 客户、公司、抬头和付款账户。
- 模板、语言、币种和税务策略。
- 周期、账单日、到期日和编号规则。
- 自动生成、自动提交审核和自动发送。
- 收件人、抄送人、明细分组和排序。

推荐始终按账单配置生成。按客户、公司、合同或业务生成是筛选和批量创建配置的辅助入口。

## 2. 多账单示例

```text
客户 A / A 网络科技有限公司

香港带宽账单
  - 香港 IP Transit / 95 带宽费
  - 香港 BGP / 接入费
  - CNY / bandwidth-95-zh

日本托管账单
  - 日本服务器 / 托管费
  - 日本服务器 / IPv4 费
  - USD / colocation-en

一次性费用账单
  - 安装费
  - 调试费
  - 手工生成
```

## 3. 重复计费检测

保存配置、启用配置、生成批次和正式化时检查：

- 一个计费项存在多个有效 `CHARGE`。
- 百分比分摊合计不是 100%。
- 固定分摊超过原金额。
- `DISPLAY_ONLY` 被计入应收。
- 计费项没有自动账单配置。
- 计费项和配置的客户、公司或币种冲突。

## 4. 模板优先级

```text
预览手工指定
  -> 账单配置
  -> 合同计费项
  -> 业务
  -> 业务分组
  -> 合同
  -> 公司
  -> 客户
  -> 币种与语言默认
  -> 系统默认
```

同一优先级多重命中属于配置错误。

## 5. 预览状态

```text
GENERATING -> DRAFT -> BUSINESS_REVIEW -> FINANCE_REVIEW -> APPROVED
     |          |             |                |
     v          v             v                v
   ERROR      VOIDED        REJECTED         REJECTED

APPROVED -> FINALIZING -> FINALIZED
```

## 6. 正式账单状态

文档状态：

```text
FINALIZING -> CONFIRMED -> SENT -> VOIDED -> REPLACED(optional)
```

正式账单只能以 `FINALIZING`、`NOT_QUEUED`、`UNPAID`、`version = 0` 且全部生命周期时间为空的状态创建；数据库拒绝直接插入“天生已确认、已发送、已作废或已付款”的正式账单，后续状态必须经过受控迁移。插入时还必须绑定刚从 `APPROVED` 进入 `FINALIZING` 的同一预览、同一审批修订和审批前内容版本，正式抬头、账期、模板、币种、金额与渲染模型必须逐项等于该已批准预览，不能由直接 SQL 替换成另一份内容。正式明细和调整必须逐列复制自该预览，来源 ID 非空且在同一正式账单内唯一；排除明细和非 `ACTIVE` 调整不能进入正式账单，确认前必须完整覆盖全部应入账来源。预览进入 `FINALIZING` 后，其明细、调整和排除项立即冻结。

`confirmed_at`、首次成功发送的 `sent_at` 和 `voided_at` 一经记录不可改写；发送成功必须同时把文档状态推进到 `SENT`。付款分配插入或从 `ACTIVE` 冲销为 `REVERSED` 时，数据库在同一事务内按有效分配和账单时区派生 `UNPAID`、`PARTIALLY_PAID`、`PAID` 或 `OVERDUE`，并同步维护 `paid_at`、`updated_at` 和版本；应用和直接 SQL 不能手工伪造这些状态。确认所用 PDF 必须是未软删除、非空、哈希一致并记录模板及渲染器版本的正式文件证据。

付款状态独立：

```text
UNPAID -> PARTIALLY_PAID -> PAID
   |              |
   +-> OVERDUE <--+
```

文档、发送和付款状态分开保存，避免组合状态爆炸。

## 7. 预览生成

1. 锁定账单配置和账期。
2. 选择有效计费项和分摊。
3. 检查合同、价格、币种和重复归属。
4. 同步或选择用量快照。
5. 运行纯计费引擎。
6. 创建明细、计算快照和异常。
7. 解析模板并生成水印 PDF。
8. 进入 `DRAFT` 或 `ERROR`。

## 8. 编辑与重新计算

允许：重新同步、重新计算、更换模板、添加调整、排除系统明细、修改备注和排序。

系统明细不允许直接覆盖成无来源的人工金额：

- 排除使用 `preview_exclusion`。
- 金额变更使用 `preview_adjustment`。
- 重算替换系统明细，保留仍有效的调整和排除意图。

## 9. 审批失效

以下变化递增预览版本并清除已有审批：

- 金额、税额、账期、币种、汇率或到期日。
- 用量快照、计费项、调整或排除项。
- 模板版本、付款账户、抬头和客户可见备注。

## 10. 两级审批

第一阶段：

```text
业务审核 -> 财务审核 -> APPROVED
```

- 业务审核检查用量、服务、合同和来源。
- 财务审核检查价格、税、调整、抬头和付款条件。
- 阻断异常不能通过。
- 超权限调整追加高级审批。
- 审批记录绑定预览版本。

## 11. 正式化

数据库事务内：

1. 锁定已批准预览。
2. 校验审批实例属于该预览、状态为 `APPROVED`，审批修订、审批前内容版本和工作流版本全部一致。
3. 通过 `source_preview_id` 检查幂等。
4. 分配正式编号。
5. 复制并冻结账单、明细、调整、快照和模板版本；数据库再次逐项校验正式账单抬头、金额、全部未排除明细和全部有效调整精确等于已批准预览。
6. 创建 `FINALIZING` 正式账单。
7. 写入 `InvoiceFinalizationRequested` Outbox。

Render Worker：

1. 使用冻结数据和模板渲染。
2. 生成 PDF、SHA-256 和文件记录。
3. 保存渲染器、Chromium 和字体版本。
4. 账单进入 `CONFIRMED`，预览进入 `FINALIZED`。
5. 如果这是更正账单，在同一数据库事务内创建唯一 `REPLACES` 关系，并把仍为 `VOIDED` 的原账单推进到 `REPLACED`；PDF 确认前不提前改变原账单状态。

渲染失败时保持 `FINALIZING` 并安全重试，不重新编号。

## 12. 编号

预览示例：`PRE-202607-CUST-0001-01`。

正式规则示例：

```text
INV-{YYYYMM}-{CUSTOMER_NO}-{SEQ}
INV-{COMPANY_CODE}-{YYYYMM}-{SEQ}
HK-{YYYYMM}-{SEQ}
```

号码分配使用数据库原子计数器。已分配号码不回收。

## 13. 冻结内容

- 客户、公司、抬头、账期、到期日和时区。
- 用量快照、价格规则和计算快照。
- 币种、汇率、税、折扣和调整。
- 模板版本、资源、列表配置和备注。
- 审批记录、正式化操作者和时间。
- PDF、文件元数据和 SHA-256。

数据库层同时冻结已发布价格阶梯、模板资源、审批步骤，正式账单引用的审批动作、用量证据
文件关联及底层文件元数据；付款、分配和退款历史禁止物理删除。

## 14. 作废与更正

```text
正式账单
  -> 作废申请和付款检查
  -> VOIDED
  -> 复制新预览
  -> 修改并重新审核
  -> 新正式账单
  -> REPLACES 关系
```

已有付款时必须先解除分配、退款或完成财务冲销。

实现约束：

- 作废命令使用 `If-Match` 和 `Idempotency-Key`，存在有效付款分配时返回冲突。
- 作废时取消尚未发送的通知和与该账单相关的待处理发送任务，但不删除历史通知日志。
- 更正预览是新的 `invoice_preview` 聚合，复制原正式账单冻结抬头、账期、明细、调整和证据引用；原正式账单内容不变。
- 更正预览仍从 `DRAFT` 开始，任何修改重新递增版本并走业务、财务审批。
- 新正式账单的 PDF 成功持久化并进入 `CONFIRMED` 时，才在同一事务内写入单一 `REPLACES` 关系并把原账单从 `VOIDED` 推进到 `REPLACED`；任一步失败都必须整体回滚，不能留下提前替换的原账单或孤立关系。

## 15. 自动生成与自动发送

- Quartz 每 5 分钟扫描月度账单配置，为上一完整自然月创建幂等预览任务。
- 自动生成同时要求租户运维开关、账单配置 `auto_generate` 和非紧急停用状态。
- `invoice.confirmed` Outbox 事件触发通知规划；自动发送同时要求租户 `auto_send_enabled`、配置快照 `auto_send=true` 和非紧急停用状态。
- Quartz 只创建 `background_jobs`，Outbox 发布和外部通知由独立 Worker 领取、租约、重试和死信。
