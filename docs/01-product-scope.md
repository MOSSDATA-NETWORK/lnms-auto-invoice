# 产品目标、范围与角色

## 1. 系统定位

Auto Invoice 是商业账单平台，不是 SNMP 采集系统、法定电子发票平台或完整会计总账。

LibreNMS 负责设备、端口、采样、Bill History、95 值和流量图；Auto Invoice 负责客户、合同、价格、金额、审批、PDF、发送、付款和审计。

## 2. 建设目标

1. 对接一个或多个 LibreNMS 实例。
2. 按客户、公司、合同计费项、账单配置和账期自动计费。
3. 同一客户、公司和账期可以生成多张独立账单。
4. 不同账单可以使用不同模板、语言、币种、抬头和付款账户。
5. 预览账单可重新同步、计算、调整和审核。
6. 正式账单冻结所有计算输入、模板版本和文件。
7. 支持通知、付款、客户确认、异议和审计。
8. 为 CRM、工单、支付、财务、电子发票和网络控制保留接口。

## 3. 第一阶段 MVP

- 客户、公司、联系人、产品、业务和服务资源。
- 合同、合同计费项、版本化价格规则和附件。
- CSV/XLSX 导入、预校验、错误报告和幂等重跑。
- LibreNMS 数据源、Bill 映射、历史同步、图像和用量快照。
- 账单配置、计费项归属、多账单和重复收费检测。
- 95、固定费、数量、阶梯、折算、最低消费、封顶和调整。
- HTML/CSS 模板、字段别名、多列表、版本和预览。
- 预览、两级审批、正式化、PDF、邮件和审计。
- 基础付款记录与付款状态。
- 本地账号、TOTP MFA、RBAC 和 OIDC 预留。

## 4. 第二阶段

- 可视化模板编辑器、DOCX、多语言和多币种。
- 汇率、客户门户、在线确认、异议、完整付款和逾期提醒。
- 流量预警、SLA 赔偿、收入、应收和利润报表。

## 5. 第三阶段

- CRM、工单、支付、ERP、电子发票和供应商账单集成。
- 经审批的停机、复机、端口开通和其他网络动作。
- 多租户 SaaS、套餐、配额、租户管理员和租户品牌。

## 6. 非目标

- 不独立采集 SNMP 或替代 LibreNMS。
- 不把 Auto Invoice 计算结果反写为 LibreNMS 原始用量。
- 首版不开具法定税务发票，不生成会计凭证。
- 模板不允许执行脚本、命令、文件访问或任意网络请求。
- 首版不自动执行停复机动作。

## 7. 角色

| 角色 | 主要职责 |
|---|---|
| 系统管理员 | 系统、用户、权限、数据源、任务和数据修复 |
| 业务人员 | 客户、业务、合同、用量核对和业务审核 |
| 财务人员 | 价格、调整、财务审核、正式化、付款和报表 |
| 销售人员 | 查看名下客户、业务和账单，提交意见 |
| 模板管理员 | 创建、测试、发布和回滚模板 |
| 审计人员 | 只读检查价格、计算、审批、账单和日志 |
| 客户用户 | 查看、下载、确认、质疑账单和上传付款凭证 |
| 集成客户端 | 通过 API/Webhook 同外部系统交换数据 |

## 8. 成功标准

- 1 万有效业务和 5 万月度明细可在性能目标内完成。
- 普通自动计费项不会被多个账单配置重复收费。
- 任意正式账单可追溯到合同、价格版本、用量快照、模板和审批。
- 后续合同、模板和 LibreNMS 变化不影响历史正式账单。
- 重复请求不会生成重复账单、编号、付款或通知。
- 新旧账单流程并行核对两个完整账期；大于一个最小货币单位的差异必须解释。

## 9. 术语

| 术语 | 定义 |
|---|---|
| 客户 `customer` | 账户或商业关系主体 |
| 公司 `company` | 签约、付款或账单抬头主体 |
| 业务 `service` | 客户实际使用的服务实例 |
| 合同计费项 `contract_item` | 自动出账最小单位 |
| 价格规则版本 | 某段有效期内不可变的计费参数 |
| 账单配置 `invoice_profile` | 决定哪些计费项合并出账及其展示和发送规则 |
| 用量快照 | 账单使用的不可变 LibreNMS 证据 |
| 预览账单 | 可以修改和重新审核的草稿 |
| 正式账单 | 已冻结且不能原地修改的商业账单 |

## 10. 业务不变量

完整不变量见根目录 [`AGENTS.md`](../AGENTS.md)。产品和实施人员尤其需要关注：

- 业务不是唯一计费单位，一项业务可以包含多个合同计费项。
- 一个客户或公司在同一账期可以有多张账单。
- 预览与正式账单严格分离。
- 正式账单必须保留计算和文件证据。
